# Инструменты ЮрИИст MCP

Сгенерировано из `tools/list` сервера (`docs/tools.json`). Право — OAuth scope, без которого инструмента нет в списке.

## ИИ-юрист (`yriist:agent`)

### `ask_yriist` — Спросить ИИ-юриста ЮрИИста

Задаёт вопрос ИИ-юристу ЮрИИста — полноценный юридический агент по праву РФ: сам ищет практику и нормы, проверяет ссылки, считает сроки и суммы, читает приложенные файлы, составляет и правит документы. Ответ сохраняется чатом в ЮрИИсте. Расходует одно сообщение тарифа.
- Продолжение разговора — chat_id (тогда дело чата не меняется: project_id только для нового чата).
- Файлы пользователя (договор, решение суда) — file_ids из file_upload / files_list: ЮрИИст прочитает их сам.
- Правка существующего документа («поправь п. 3.2») — document_id: ЮрИИст изменит этот документ, появится новая версия.
- Вопрос по делу — project_id: ЮрИИст учтёт «О деле», файлы и факты дела.
Ответ может готовиться несколько минут, составление документа — почти всегда дольше ожидания: при status=running вызови chat_read с chat_id позже — там будут ответ и document_id созданных документов. Отмена вызова до отправки вопроса ничего не списывает; после — ответ дописывается и сохраняется в чате (сообщение списано), прочитать его — chat_read, остановить — chat_stop. Для точечных проверок есть court_search, law_article, calculate_*.

Параметры: `question`, `chat_id`?, `project_id`?, `file_ids`?, `document_id`?, `audience`?, `deep_research`?, `wait_seconds`? · карточка: `ui://yriist/answer.html`

### `chat_stop` — Остановить ответ

Останавливает ответ ЮрИИста, который ещё готовится в чате (после ask_yriist со status=running), — например, если вопрос задан неверно. Уже написанная часть сохранится. Сообщение тарифа уже потрачено.

Параметры: `chat_id` · карточка: `ui://yriist/answer.html`

## Ваши данные (чтение) (`yriist:read`)

### `whoami` — Мой аккаунт ЮрИИста

Аккаунт ЮрИИста, к которому подключено это приложение: имя, тариф, сколько сообщений осталось в этом месяце, какие возможности открыты на тарифе (документы, дела, табличный анализ, глубокий поиск, скачивание файлов), лимиты хранилища и выданные права подключения. Вызывай, чтобы заранее понять, что пользователь может сделать в ЮрИИсте, или когда он спрашивает про свой тариф.

Параметры: — · карточка: `ui://yriist/account.html` · только чтение

### `chats_list` — Чаты ЮрИИста

Чаты пользователя с ИИ-юристом ЮрИИста (личное пространство), новые первыми: id, название, дата, дело, идёт ли ответ сейчас. Фильтры: слова из названия (query), дело (project_id). Текст чата — chat_read; поиск по словам внутри переписки — chats_search.

Параметры: `query`?, `project_id`?, `limit`?, `offset`? · карточка: `ui://yriist/list.html` · только чтение

### `chat_read` — Прочитать чат

Текст чата с ЮрИИстом в Markdown (вопросы пользователя и ответы ЮрИИста), документы, созданные в чате (document_id), приложенные файлы (file_id) и идёт ли ответ сейчас (status=running). Так же проверяется ответ после ask_yriist со status=running. Длинный чат приходит последними сообщениями; более ранние — from_message.

Параметры: `chat_id`, `max_chars`?, `from_message`? · карточка: `ui://yriist/answer.html` · только чтение

### `chats_search` — Поиск по чатам

Полнотекстовый поиск по переписке пользователя с ЮрИИстом (русская морфология): найдёт, где обсуждались слова, суммы, стороны. Возвращает фрагменты и chat_id. Можно ограничить делом (project_id).

Параметры: `query`, `project_id`?, `limit`? · карточка: `ui://yriist/list.html` · только чтение

### `projects_list` — Дела

Дела пользователя в «Делах» ЮрИИста (личное пространство) — папки для клиентского дела или спора, где лежат чаты, файлы, документы, сроки и судебные дела. Новые по активности первыми; поиск по названию. Содержимое дела — project_read.

Параметры: `query`?, `limit`?, `cursor`? · карточка: `ui://yriist/list.html` · только чтение

### `project_read` — Дело

Всё о деле из «Дел» ЮрИИста: «О деле» (номер, суд, стороны, описание), чаты, файлы (file_id), документы (document_id), сроки и отслеживаемые судебные дела (case_id).

Параметры: `project_id` · только чтение

### `files_list` — Файлы ЮрИИста

Файлы пользователя в ЮрИИсте (личное пространство): загруженные в хранилище, в дела и в чаты, новые первыми — file_id, имя, размер, дело, чат. Фильтры: имя (query), дело (project_id). Текст файла — file_read; вопрос по файлу — ask_yriist с file_ids.

Параметры: `query`?, `project_id`?, `kind`?, `limit`?, `offset`? · карточка: `ui://yriist/list.html` · только чтение

### `file_read` — Прочитать файл

Текст файла пользователя из ЮрИИста: PDF (со страницами «стр. N»), DOCX, DOC, RTF, таблицы, сканы и фото (распознавание текста). Скан читается дольше: если текст ещё не готов, придёт status=processing — вызовите file_read с тем же file_id через 20–30 секунд. Длинный текст — частями: from_char и max_chars.

Параметры: `file_id`, `from_char`?, `max_chars`?, `wait_seconds`? · только чтение

### `documents_list` — Документы ЮрИИста

Документы пользователя в «Документах» ЮрИИста (личное пространство): договоры, претензии, иски, созданные в чатах, из шаблонов или загруженные; новые по изменению первыми. Фильтры: название (query), вид (text — документ, sheet — таблица), дело (project_id), чат (chat_id). Текст — document_read.

Параметры: `query`?, `kind`?, `project_id`?, `chat_id`?, `limit`?, `offset`? · карточка: `ui://yriist/list.html` · только чтение

### `document_read` — Прочитать документ

Текст документа из «Документов» ЮрИИста по абзацам: каждый абзац с номером [n] — эти номера и цитаты использует document_edit. Длинный документ — частями: from_paragraph. Таблица — как CSV. Старая версия — version из document_versions.

Параметры: `document_id`, `from_paragraph`?, `version`?, `max_chars`? · только чтение

### `document_versions` — Версии документа

История версий документа, новые первыми: время версии (её id для document_read version и document_restore), название, размер.

Параметры: `document_id` · только чтение

### `document_export` — Скачать документ

Готовит файл документа для скачивания: DOCX или PDF (таблица — XLSX или CSV) из последней сохранённой версии и возвращает ссылку на 7 дней. Ссылка открывает файл без входа — давайте её только пользователю.

Параметры: `document_id`, `format` · только чтение

### `templates_search` — Шаблоны документов

Поиск по библиотеке из 230+ проверенных шаблонов ЮрИИста (договоры, иски, претензии, доверенности, заявления…). Смысловой поиск по query; без query — все шаблоны категории. Категории: Договоры, Исковые заявления, Претензии, Заявления, Доверенности, Акты, Расписки, Соглашения, Жалобы, Ходатайства и возражения, Согласия, Корпоративные документы, Уведомления, Кадровые документы, Письма и запросы, Коммерческие документы. Текст шаблона — template_read; копия в документы пользователя — document_from_template.

Параметры: `query`?, `category`?, `limit`?, `offset`? · карточка: `ui://yriist/list.html` · только чтение

### `template_read` — Текст шаблона

Полный текст шаблона из библиотеки ЮрИИста: структура, обязательные реквизиты, ссылки на нормы. Используй как основу документа.

Параметры: `template_id` · только чтение

### `deadlines_list` — Сроки

Сроки пользователя из «Сроки» ЮрИИста: процессуальные и договорные, с последним днём, основанием (норма), делом и судебным делом. По умолчанию — открытые, ближайшие первыми. Фильтры: окно (today / week / overdue), даты, дело (project_id), судебное дело (case_id). Новый срок — deadline_save; изменить, выполнить, снять — deadline_update.

Параметры: `status`?, `window`?, `due_from`?, `due_to`?, `project_id`?, `case_id`?, `limit`?, `offset`? · карточка: `ui://yriist/deadlines.html` · только чтение

### `cases_list` — Дела на мониторинге

Судебные дела, которые ЮрИИст отслеживает для пользователя: номер, суд, стороны, статус, последнее событие, открытые сроки, case_id. Карточка с актами и заседаниями — case_read; поставить новое — case_track; пауза или закрытие — case_update.

Параметры: `status`?, `project_id`? · карточка: `ui://yriist/list.html` · только чтение

### `case_read` — Карточка дела

Карточка отслеживаемого судебного дела: суд, стороны, статус мониторинга, все события (судебные акты со ссылками и кратким содержанием, заседания с датой, временем и залом) и сроки по делу.

Параметры: `case_id`, `max_events`? · только чтение

### `review_tables_list` — Табличный анализ

Таблицы «Табличного анализа» пользователя (сводная таблица по многим документам: строка — документ, колонка — вопрос): review_id, название, документов готово, ячеек на проверку. Содержимое — review_table_read.

Параметры: `limit`? · карточка: `ui://yriist/list.html` · только чтение

### `review_table_read` — Таблица анализа

Читает таблицу «Табличного анализа»: по каждому документу — ячейки колонок, комментарии, уверенность, ячейки на проверку, по желанию цитаты. Пока таблица заполняется, недоделанные документы помечены — перечитайте позже.

Параметры: `review_id`, `columns`?, `documents`?, `only_flagged`?, `quotes`? · только чтение

### `memory_list` — Память ЮрИИста

Что ЮрИИст помнит: факты о пользователе (profile), заметки этого подключения (connection), с project_id — факты дела, с chat_id — факты чата. С id — для memory_delete («забудь…», «что ты обо мне помнишь»).

Параметры: `scope`?, `project_id`?, `chat_id`? · только чтение

### `memory_search` — Поиск в памяти ЮрИИста

Ищет по смыслу в памяти ЮрИИста: факты о пользователе, заметки подключения, с project_id — факты дела (стороны, суммы, даты, номера, предпочтения). Весь список — memory_list. Переписку чатов ищет chats_search.

Параметры: `query`, `scope`?, `project_id`?, `chat_id`? · только чтение

## Действия (`yriist:write`)

### `chat_delete` — Удалить чат

Удаляет чат пользователя в ЮрИИсте безвозвратно: переписку, файлы, приложенные только к этому чату, и факты памяти этого чата. Документы, созданные в чате, остаются в «Документах». Только по явной просьбе пользователя удалить чат.

Параметры: `chat_id`

### `project_create` — Создать дело

Создаёт дело в «Делах» ЮрИИста (папку для клиентского дела или спора) с «О деле»: номер, суд, стороны, описание — их ЮрИИст учитывает в каждом чате дела. Если дело с таким названием уже есть, вернёт его. Потом в дело можно класть файлы (file_upload с project_id), документы, сроки и вопросы (ask_yriist с project_id). Доступно на платных тарифах.

Параметры: `name`, `description`?, `details`? · карточка: `ui://yriist/list.html`

### `project_update` — Изменить дело

Переименовывает дело или меняет «О деле» (описание, номер, суд, наша и другая сторона). Указанные поля заменяются, остальные остаются; пустая строка или null — стереть поле.

Параметры: `project_id`, `name`?, `description`?, `details`? · карточка: `ui://yriist/list.html`

### `project_delete` — Удалить дело

Удаляет дело из «Дел» безвозвратно: ВСЕ файлы дела (из хранилища) и память дела. Чаты дела по умолчанию остаются без дела (chats=keep), chats=delete удаляет и их. Документы остаются в «Документах». Только по явной просьбе пользователя удалить дело; confirm_name — точное название дела, как в projects_list.

Параметры: `project_id`, `confirm_name`, `chats`?

### `file_upload` — Загрузить файл (небольшой)

Загружает небольшой файл (до 2.5 МБ) в ЮрИИст целиком в вызове — content_base64. Для файлов больше или если есть терминал — file_upload_begin (ссылка для PUT) и file_upload_finish. Файл попадает в хранилище пользователя (или в дело с project_id); дальше — file_read, ask_yriist с file_ids. PDF, DOCX, DOC, RTF, ODT, TXT, XLSX, сканы и фото.

Параметры: `name`, `content_base64`, `mime_type`?, `project_id`? · карточка: `ui://yriist/list.html`

### `file_upload_begin` — Начать загрузку файла

Шаг 1 загрузки файла в ЮрИИст (до 300,0 МБ): проверяет место на тарифе и возвращает upload_url — загрузите файл туда HTTP PUT с заголовком Content-Type: <content_type из ответа> (например, curl -X PUT -H "Content-Type: …" --upload-file файл "<upload_url>"), затем вызовите file_upload_finish с upload_id. Ссылка действует час. Если такой файл уже есть (тот же sha256), PUT не нужен — сразу file_upload_finish. Без терминала и для файлов до 2,5 МБ — file_upload.

Параметры: `name`, `size`, `mime_type`?, `sha256`?, `project_id`?

### `file_upload_finish` — Завершить загрузку файла

Шаг 2 загрузки: регистрирует файл, загруженный по upload_url из file_upload_begin, и возвращает file_id. Повторный вызов с тем же upload_id вернёт тот же файл.

Параметры: `upload_id` · карточка: `ui://yriist/list.html`

### `document_create` — Создать документ в ЮрИИсте

Сохраняет готовый текст (Markdown: заголовки, списки, таблицы, **жирный**) как документ в «Документы» ЮрИИста — там его можно править в редакторе, скачать DOCX/PDF (document_export), подписать и отправить. Можно сразу положить в дело (project_id). Считается в лимит создания документов тарифа. request_id (любой UUID) делает вызов безопасным для повтора: тот же request_id вернёт тот же документ.

Параметры: `title`, `content`, `project_id`?, `request_id`? · карточка: `ui://yriist/list.html`

### `document_edit` — Править документ

Вносит правки в документ из «Документов» ЮрИИста как написано — без пересказа другой моделью; получается новая версия (старая остаётся в document_versions). Сначала document_read: правки ссылаются на абзацы [n] и цитаты из него. Операции: replace (find → text), replace_paragraph (весь абзац → text), insert_after / insert_before (новые абзацы text после/перед абзацем с find), delete (удалить find), delete_paragraph. Каждая операция применяется сама по себе: что не подошло, вернётся с причиной и текущим текстом абзаца — повторите только её. Для правки «по смыслу» («смягчи ответственность») — ask_yriist с document_id.

Параметры: `document_id`, `edits`, `base_revision`? · карточка: `ui://yriist/list.html`

### `document_update` — Переименовать или переместить документ

Переименовывает документ (title) и/или кладёт его в дело (project_id; null — убрать из дела). Текст не меняется — для правок document_edit.

Параметры: `document_id`, `title`?, `project_id`? · карточка: `ui://yriist/list.html`

### `document_restore` — Восстановить версию документа

Восстанавливает версию документа из document_versions: её текст становится новой текущей версией, вся история сохраняется (так отменяется неудачная правка).

Параметры: `document_id`, `version` · карточка: `ui://yriist/list.html`

### `document_delete` — Удалить документ

Удаляет документ из «Документов» безвозвратно: все версии и файлы DOCX. Только по явной просьбе пользователя удалить документ.

Параметры: `document_id`

### `document_from_template` — Документ из шаблона

Копирует шаблон из библиотеки в «Документы» пользователя (можно сразу в дело — project_id). Копия — как в шаблоне: заполните её через document_edit (по абзацам из document_read) или в редакторе ЮрИИста.

Параметры: `template_id`, `title`?, `project_id`? · карточка: `ui://yriist/list.html`

### `deadline_save` — Сохранить срок

Сохраняет срок в «Сроки» ЮрИИста с напоминаниями (push, email, календарь) — только по просьбе пользователя сохранить или напомнить. Два способа:
1) Расчётный срок: rule (вид срока, как в calculate_deadline) или procedure + length_value, и event_date — последний день считает движок сроков по производственному календарю, а не модель.
2) Срок с известной датой (договорной, «оплата до 15.12.2026»): title + due_date без rule.
Можно привязать к делу (project_id) и судебному делу (case_id из cases_list). Такой же открытый срок не дублируется — вернётся существующий.

Параметры: `rule`?, `procedure`?, `length_value`?, `length_unit`?, `day_kind`?, `event_date`?, `alt_event_date`?, `due_date`?, `title`?, `legal_basis`?, `note`?, `project_id`?, `case_id`? · карточка: `ui://yriist/deadlines.html`

### `deadline_update` — Изменить срок

Меняет срок в «Сроки» ЮрИИста: отметить выполненным (status=done), снять с контроля (dismissed), вернуть в работу (open); поправить название, заметку, основание; новая дата начала (расчётный срок пересчитается) или новый последний день (срок с известной датой); привязать к делу или судебному делу; подтвердить дату («Дата верна», confirmed=true). Только по просьбе пользователя.

Параметры: `deadline_id`, `status`?, `title`?, `note`?, `legal_basis`?, `trigger_date`?, `due_date`?, `project_id`?, `case_id`?, `confirmed`? · карточка: `ui://yriist/deadlines.html`

### `deadline_delete` — Удалить срок

Удаляет срок из «Сроков» ЮрИИста безвозвратно, с напоминаниями. Если срок просто выполнен или больше не нужен — лучше deadline_update со status=done или dismissed (останется в истории). Только по явной просьбе удалить.

Параметры: `deadline_id`

### `deadline_complete` — Срок выполнен

Устарело, используйте deadline_update. Отмечает срок выполненным (status=done), снимает с контроля (dismissed) или возвращает в работу (open).

Параметры: `deadline_id`, `status`? · карточка: `ui://yriist/deadlines.html`

### `case_track` — Отслеживать дело

Ставит судебное дело на мониторинг в ЮрИИсте: новые акты и заседания приходят уведомлением, сроки обжалования попадают в «Сроки». Номер и суд — из court_case. Для дел судов общей юрисдикции суд обязателен (номера повторяются). Если номер найден в нескольких судах, ответ перечислит их: спроси пользователя, какой его, и вызови case_update с court. Только по просьбе пользователя.

Параметры: `case_number`, `court`?, `uid`?, `title`?, `project_id`? · карточка: `ui://yriist/list.html`

### `case_update` — Изменить дело на мониторинге

Меняет отслеживаемое судебное дело: пауза (status=paused), снова отслеживать (active), дело окончено (closed); название; суд (для номера, найденного в нескольких судах, — история загрузится заново); дело в «Делах» (project_id, null — убрать). Только по просьбе пользователя.

Параметры: `case_id`, `status`?, `court`?, `title`?, `project_id`? · карточка: `ui://yriist/list.html`

### `case_check` — Проверить дело сейчас

«Проверить сейчас»: ЮрИИст сразу проверяет отслеживаемое дело в базе решений и на сайте суда (обычно это делается само по расписанию). Новые акты становятся событиями и сроками, как при плановой проверке. Не чаще 10 раз в час.

Параметры: `case_id` · карточка: `ui://yriist/list.html`

### `case_delete` — Удалить дело с мониторинга

Удаляет судебное дело из мониторинга безвозвратно, со всеми его событиями. Если дело просто закончилось — лучше case_update со status=closed (история останется). Только по явной просьбе удалить.

Параметры: `case_id`

### `review_table_create` — Создать табличный анализ

Создаёт «Табличный анализ»: ЮрИИст сам читает каждый файл (file_ids из file_upload / files_list) и заполняет таблицу — строка на документ, колонка на вопрос (стороны, сроки, суммы, риски…). Колонки — готовый шаблон (template) или свои (columns: label + prompt). Таблица заполняется в фоне несколько минут: ответ придёт сразу с review_id, результат — review_table_read. Дорогая операция: на тарифе «Премиум», до 10 таблиц в час. Шаблоны:
- contract_key_terms: Ключевые условия договоров — Любые договоры и дополнительные соглашения
- contract_playbook: Проверка по стандартам компании — Договоры контрагентов на согласовании
- supply: Договоры поставки — Договоры поставки, спецификации
- lease: Договоры аренды — Договоры аренды помещений, зданий, земли, оборудования
- employment: Трудовые договоры (ТК РФ) — Трудовые договоры и дополнительные соглашения к ним
- nda: Соглашения о конфиденциальности (NDA) — NDA, соглашения о конфиденциальности
- due_diligence: Due diligence договоров (M&A) — Договоры целевой компании из data room
- primary_docs: Первичные документы (бухгалтерия) — Счета, УПД, акты, ТОРГ-12, счета-фактуры, акты сверки
- court_acts: Судебные акты — Решения, постановления, определения судов
- procurement: Госконтракты (44-ФЗ / 223-ФЗ) — Контракты и проекты контрактов
- incoming: Входящие письма и претензии — Претензии, требования, уведомления, запросы госорганов, повестки

Параметры: `file_ids`, `template`?, `columns`?, `title`?, `project_id`? · карточка: `ui://yriist/list.html`

### `memory_save` — Запомнить в ЮрИИсте

Сохраняет факты в долговременную память ЮрИИста — только по просьбе пользователя запомнить. Каждый факт — самодостаточное утверждение с конкретикой («Работодатель — ООО «Ромашка», ИНН 7701234567»). scope: profile — о пользователе, ЮрИИст учтёт во всех чатах; project — факт дела (нужен project_id), учтётся во всех чатах дела; connection — заметка этого подключения.

Параметры: `facts`, `project_id`?

### `memory_delete` — Забыть в ЮрИИсте

Удаляет устаревшие или ошибочные факты из памяти ЮрИИста по id из memory_list / memory_search — когда пользователь просит забыть или факт изменился. Для фактов дела и чата передайте тот же project_id / chat_id, что при чтении.

Параметры: `ids`, `reason`?, `project_id`?, `chat_id`?

## Исследование и расчёты (`yriist:research`)

### `anonymize` — Обезличить текст

Анонимайзер ЮрИИста: убирает персональные данные (ФИО, телефоны, адреса, паспорта, ИНН, счета, e-mail…) из текста или файла пользователя (file_id) и возвращает обезличенный текст с метками вроде [ФИО-1], [ТЕЛЕФОН-2] и сводку, что заменено. Исходные значения в ответ не включаются. Удобно перед тем, как передать документ дальше. Считается в лимит анонимайзера тарифа.

Параметры: `text`?, `file_id`? · только чтение

### `web_search` — Поиск в интернете

Поиск в российском интернете (Яндекс и др.) через ЮрИИст. До 4 запросов за вызов. Результаты с номерами [n] — откройте лучшие через web_fetch по номеру и опирайтесь на прочитанный текст, а не на сниппеты.

Параметры: `queries`, `recency`? · карточка: `ui://yriist/research.html` · только чтение

### `web_fetch` — Чтение страниц

Читает веб-страницы и документы по ссылке: результаты web_search, court_search и court_case по номеру [n] или любую публичную страницу по полному URL (http/https). Небольшие источники возвращаются целиком, большие — частями: укажи query, чтобы получить релевантные части, или parts с номерами частей. До 5 источников за вызов. Числа (проценты, суммы, сроки, даты) бери только из прочитанного текста. Страницы, где нужен вход, прочитать нельзя.

Параметры: `sources` · карточка: `ui://yriist/research.html` · только чтение

### `court_search` — Судебная практика

Судебная практика РФ по смыслу (СОЮ, арбитраж, ВС с Пленумами и обзорами, часть КСОЮ): лучшие решения [n] с мотивировкой и итогом. Дело по номеру, УИД или ссылке — court_case; полный текст решения — web_fetch по номеру [n] с query.

Параметры: `query`, `category`?, `court_level`?, `court`?, `judge`?, `article`?, `doc_type`?, `party`?, `party_role`?, `date_from`?, `date_to`?, `outcome`?, `list`?, `alt_queries`?, `situation`? · карточка: `ui://yriist/research.html` · только чтение

### `court_case` — Карточка дела

Решение по номеру дела, УИД или ссылке: база с учётом суда и нижестоящей инстанции, иначе официальные сайты. Пользователь назвал дело — сначала court_case, не court_search.

Параметры: `case_number`?, `uid`?, `url`?, `court`?, `date`? · карточка: `ui://yriist/research.html` · только чтение

### `law_article` — Текст нормы

Текст статьи кодекса или закона (или пункта Пленума ВС/ВАС) в действующей редакции, сверенный по нескольким источникам, с номером [n]. Знаешь акт и статью — бери здесь, не поиском. В базе кодексы, 96 основных законов (по номеру или названию: «127-ФЗ», «ЗоЗПП»), ПДД РФ (article — пункт: «12.4») и Пленумы (по номеру и дате). Закона нет в базе — укажи вид, дату и номер («Федеральный закон от 27.11.2018 № 422-ФЗ»), так найдётся и он; у постановления Правительства article — пункт утверждённых им Правил. В ответе «Рядом в этом акте»: если нужного (срока, суммы, условия, круга лиц, исключения) в статье нет, открой соседнюю, прежде чем отвечать.

Параметры: `articles` · карточка: `ui://yriist/research.html` · только чтение

### `check_norms` — Актуальность норм

Актуальность норм: по каждой ссылке в тексте — утратила силу (и что вместо), не вступила (с какой даты), недавно изменена, нет такой статьи или части. Передай текст (черновик, фрагмент договора; текст файла — из file_read) или список ссылок. ✗ — не приводи норму как действующую.

Параметры: `text`?, `citations`? · карточка: `ui://yriist/research.html` · только чтение

### `verify_claims` — Проверка ссылок и цифр

Проверка ссылок и цифр перед итоговым ответом на правовой вопрос: нормы, Пленумы и дела существуют, часть и подпункт есть, числа совпадают с текстом, решающая норма не специальная другая, итог дела верен. Выводы «нельзя / не вправе / обязан / не требуется / только» сверяет со всей статьёй — передавай их с нормой. Пересчитывает сроки (срок + дата начала + последний день), госпошлины и «a × b = c». ✗ — исправь вывод по тексту и проверь снова.

Параметры: `claims` · карточка: `ui://yriist/research.html` · только чтение

### `company_lookup` — Карточка компании

Карточка компании или ИП из ЕГРЮЛ/ЕГРИП: наименование, ИНН, ОГРН, КПП, адрес, руководитель, статус. По ИНН/ОГРН — точно, по названию — до 5 вариантов. Учредители, суды, долги, риски — company_check.

Параметры: `query` · карточка: `ui://yriist/research.html` · только чтение

### `company_check` — Проверка контрагента

Проверка контрагента по открытым реестрам: учредители, недостоверность, массовость, дисквалификация, РНП, санкции, банкротство, недоимка, суды, ФССП, отчётность, госзакупки, история изменений. Физлицо по ИНН (target=person) — где руководитель или учредитель. Платный: только когда просят проверить контрагента, оценить риски сделки или найти суды и долги; реквизиты — company_lookup.

Параметры: `query`, `target`?, `sections`? · карточка: `ui://yriist/research.html` · только чтение

### `requisites_lookup` — Реквизиты

Справочные реквизиты: bank — по БИК, ИНН или названию; court — по названию, коду или «судебный участок N город»; tax_office — по коду, названию или адресу; address — нормализация (индекс, ОКТМО, ОКАТО, ИФНС, кадастровый номер).

Параметры: `kind`, `query` · карточка: `ui://yriist/research.html` · только чтение

### `calculate_penalty` — Расчёт неустойки

Проценты и неустойки за просрочку денежного обязательства по ключевой ставке: периоды, моратории, частичные оплаты, риск снижения по ст. 333 ГК.

Параметры: `type`, `debt_rub`, `start_date`, `end_date`, `subject`?, `payments`?, `contractual_rate_percent`?, `contractual_rate_period`?, `zozpp_claim`?, `contract_price_rub`? · карточка: `ui://yriist/research.html` · только чтение

### `calculate_court_fee` — Расчёт госпошлины

Госпошлина по действующему НК РФ (ст. 333.19, 333.21) с льготами. Ставка зависит от вида производства, не от суда: жалоба в ВС — supreme_court_complaint с court по виду дела. Моральный вред — не в claim_amount_rub, а в non_property_claims. КБК не называй: реквизиты — на сайте суда.

Параметры: `court`, `claim`, `separate_dispute_claim`?, `payer`, `bankruptcy_applicant`?, `claim_amount_rub`?, `non_property_claims`?, `payer_status`?, `filing_date`? · карточка: `ui://yriist/research.html` · только чтение

### `calculate_deadline` — Расчёт процессуального срока

Срок по производственному календарю РФ (2020–2027): дни по правилу кодекса, месяцы, годы, перенос с выходных, статус на сегодня. Любой срок с датой считай здесь, не в уме. Неясно, от какого события считать (вынесение, полный текст, получение копии), — передай обе даты. rule: кодекс.вид; cassation — в КСОЮ или АС округа, presidium_cassation — в президиум областного суда, vs_cassation — в СК ВС, simplified_motivated — заявление о мотивированном решении. Нет правила — procedure и length_value/length_unit.

Параметры: `rule`?, `procedure`?, `length_value`?, `length_unit`?, `day_kind`?, `event_date`, `challenged_act`?, `alt_event_date`? · карточка: `ui://yriist/research.html` · только чтение

### `calculate` — Точный расчёт

Точная арифметика (суммы, доли, проценты, деньги до копейки): каждое число ответа бери отсюда. Шаг — формула с числами и именами прошлых шагов. Десятичная запятая («0,4484»), «%» — сотая доля, round(x; 2), min, max; без round не округляет. Метод (method) выбираешь ты; есть расчёт пользователя — сначала воспроизведи его, другой метод — только с нормой или практикой.

Параметры: `method`, `steps`, `share_denominator`?, `sum_check`? · карточка: `ui://yriist/research.html` · только чтение
